## Original contract and review lenses

Preserve the existing provider-neutral seven-event browser fixture, every native
frame string/error, native CLI status/replay/usage behavior, typed event ordering,
counts, validation obligations and checkpoint/resume labels. This is a synthetic
fixture projection, not edits, validation execution, semantic closure, live
provider capture or external receipt verification. Source-pointer counts are
observations, not unique fetched/verified source identities. No private-session
or transcript ingestion is added; PRODUCT_PLAN and MAINTENANCE retain that boundary.

Implementing-agent role lenses, not independent human approval:

- Session Safety: all inputs/fixtures remain the existing public synthetic data;
  no private material, credentials, sessions or capture fields are accepted.
- Context Boundary: WITNESS projects events; LATTICE retains semantic closure,
  and FLETCH/MDCROP retain acquisition/selection. No new closure engine or event
  meaning is introduced by delivery/lifecycle work.
- Provider Portability: preserve the original core/schema and public fixture
  vocabulary. No provider adapter or normalization silently drops ordering or
  invents evidence. Browser fixture and native CLI fixture are distinct.
- Harness Runtime: compare every native prefix/error byte, keep the CLI proof,
  reject stale worker results/exports and record actual failures before repair.

injected pending-response control, not a naturally slow Rust computation. It
proves the current-input export gap before changing production code.
